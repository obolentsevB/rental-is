# rental-is — Інформаційна система сервісу подобової оренди житла

Навчальний проєкт з дисципліни «Проєктування інформаційних систем» (НТУУ «КПІ ім. Ігоря Сікорського»).
Репозиторій організовано як єдине сховище артефактів SDD-циклу.

## Призначення

rental-is — веб-система подобової оренди житла. Власники публікують оголошення про квартири й апартаменти, а гості перевіряють доступність дат, бронюють житло онлайн і розраховуються з власниками через платформу.

Система замінює ручне ведення календаря автоматичною перевіркою доступності в момент бронювання та єдиними правилами розрахунків для обох сторін. Так вона запобігає подвійним бронюванням і фіксує домовленості про оплату й повернення коштів. Платіжні операції імітуються, реальний платіжний провайдер не залучається.

Ролі: гість, власник, модератор. Повний опис задуму: [spec/idea.md](spec/idea.md), вимоги: [spec/srs.md](spec/srs.md).

Поточна реалізація охоплює житло й бронювання, тобто 12 із 35 операцій контракту. Обмеження описано в [logs/lab5-scope.md](logs/lab5-scope.md).

## Структура
- `spec/`  — специфікації та опис задуму (джерело істини для рішень)
- `src/`   — програмний код
- `tests/` — модульні та інтеграційні тести
- `docs/`  — документація, діаграми, конвенції
- `logs/`  — журнали взаємодії з кодинговим агентом, записи рішень і контрольних точок

## Вимоги

- Python 3.14.
- Windows або Linux.
- Node.js потрібен лише для повторної збірки `docs/api.html`.
- PowerShell потрібен для `scripts/contract_check.ps1`. У Linux це PowerShell 7 (`pwsh`).

## Встановлення

Усі команди виконуються з кореня репозиторію. Якщо наведено один блок, команда однакова для PowerShell і bash.

Створити віртуальне середовище.

PowerShell:

```powershell
py -3.14 -m venv .venv
```

bash:

```bash
python3.14 -m venv .venv
```

Активувати його. Це потрібно в кожному новому терміналі.

PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

bash:

```bash
source .venv/bin/activate
```

Якщо PowerShell блокує запуск скриптів, спершу дозвольте їх для поточного сеансу:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Встановити залежності:

```shell
pip install -r requirements.txt
```

## Запуск сервера

Звичайний запуск, адреса `http://127.0.0.1:8000`:

```shell
uvicorn src.main:app
```

Сховище токенів у цьому режимі порожнє, тому працюють лише операції без входу: `GET /listings` і `GET /listings/{listingId}` для опублікованого житла. Решта операцій відповідає 401.

Запуск із тестовими токенами, адреса `http://127.0.0.1:8765`:

```shell
python scripts/serve_contract.py
```

## Конфігурація

Змінних середовища й файлів конфігурації немає.

**Порт.** Для `uvicorn` порт задає параметр `--port`:

```shell
uvicorn src.main:app --port 9000
```

У `scripts/serve_contract.py` адресу задають константи `HOST` і `PORT`. Якщо змінити порт там, цю саму адресу треба вказати в `scripts/contract_check.ps1`.

**Тестові токени.** Їх створює лише `scripts/serve_contract.py`. Токен передають у заголовку `Authorization: Bearer <токен>`.

| Токен | Роль |
|-------|------|
| `guest-token` | GUEST |
| `host-token` | HOST |
| `moderator-token` | MODERATOR |

Кожному токену призначається новий `userId` під час кожного запуску.

**Сховище.** Житло, бронювання й токени зберігаються лише в пам'яті процесу, тому після перезапуску сервера дані зникають. З цієї ж причини сервер слід запускати в одному процесі, без `--workers`.

## Тести

Модульні та API-тести:

```shell
pytest
```

Лінтер:

```shell
ruff check src tests
```

Перевірка форматування:

```shell
ruff format --check src tests
```

Правила описано в [docs/coding-convention.md](docs/coding-convention.md).

Контрактна перевірка schemathesis звіряє роботу сервера з `api/openapi.yaml` для кожного тестового токена. Спершу запустіть `python scripts/serve_contract.py` в окремому терміналі, а потім виконайте перевірку в терміналі з активованим середовищем.

PowerShell:

```powershell
.\scripts\contract_check.ps1
```

bash:

```bash
pwsh scripts/contract_check.ps1
```

Ненульовий код виходу означає, що знайдено невідповідності. Попередження `Authentication failed` для окремих операцій очікуване: деякі операції заборонені певній ролі.

## Документація

- **Контракт API:** [docs/api.html](docs/api.html), версія 1.1.0, джерело: [api/openapi.yaml](api/openapi.yaml).
- **Swagger UI:** сторінка `/docs` запущеного сервера, наприклад `http://127.0.0.1:8765/docs`. Для операцій із входом натисніть **Authorize** і введіть тестовий токен. Swagger UI будує опис із коду, тому для кожної операції показує лише код успіху й 422. Повний перелік кодів відповідей і опис операцій містить `docs/api.html`.
- **Архітектура й довідник коду (Sphinx):** після збірки відкрийте `docs/reference/_build/html/index.html`.

Зібрати документацію Sphinx:

```shell
sphinx-build -W -b html docs/reference docs/reference/_build/html
```

Зібрати `docs/api.html` заново:

```shell
npx @redocly/cli@2.76.0 build-docs api/openapi.yaml --output docs/api.html
```
