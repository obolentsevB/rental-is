## Нова поведінка

Нова поведінка, якої немає в базовій SRS, оформлена адендумом ADD-01
(PHOTO_INVALID, перелік звернень і повідомлення модераторам) і внесена в
SRS v1.1 до формування контракту (`logs/gate-spec.md`, «Перегляд після
ADD-01»). Контракт не вводить відмов, яких SRS не передбачає: загальні коди
лише називають уже визначені відмови.

## Застереження

1. **Попередження `info-license` залишено свідомо.** Це внутрішній API
   навчального проєкту, ліцензію не визначено; вигадана ліцензія була б
   неправдивою.
2. **Mock не зберігає стан.** Правила, що залежать від попередніх операцій
   (перетин із підтвердженим бронюванням, перерва після COMPLETED — K-135,
   лічильник скасувань), mock лише імітує через заголовок `Prefer`.
   Реально вони перевірятимуться модульними тестами в ЛР №5 за TDD (NFR-02).
3. **Межі значень, які залежать від даних** (кількість осіб відносно
   житла, ціна 0,01…1 000 000,00), схемою не обмежуються; їх перевіряє
   сервер. Причина — порядок перевірок FR-07 (зворотне коригування №3).
4. **OQ-06 відкрите:** не визначено, чи можна заблокувати модератора.
   Контракт не змінено; рішення — через уточнення SRS.
5. **Пагінації немає** в жодному переліку; жодна вимога її не вимагає.
   Для журналу подій (24 місяці записів) це варто переглянути до
   реалізації.
6. **T-03 закрито частково:** контракт API готовий, вибір стеку й модель
   даних лишаються в T-03 до Е0-GATE.
