# Конвенція коду

Стек: Python 3.14, FastAPI. Налаштування інструмента — секції `[tool.ruff]` у `pyproject.toml`.
Конвенція повідомлень комітів описана окремо: `docs/commit-convention.md`.

## Обрана основа

- **PEP 8** — загальноприйнятий стиль Python. FastAPI власного стилю не задає, тому окрема база не потрібна.
- **PEP 257** — базові вимоги до docstring-ів. Стиль Google додає до них секції `Args`, `Returns`, `Raises`, які зручно читати у вихідному коді.
- **ruff** — один інструмент і для лінтингу, і для форматування, з однією конфігурацією. Він замінює окремі flake8, isort, pydocstyle і black.

## Правила

Колонка «Перевірка» показує, що саме контролює дотримання правила.

| Тема | Правило | Перевірка |
|------|---------|-----------|
| Довжина рядка | Не більше 100 символів. Форматер переносить код, але не розбиває довгі рядкові літерали, коментарі й docstring-и: їх скорочують вручну. | `E501`, `ruff format` |
| Форматування | Рядки в подвійних лапках. Решту оформлення визначає форматер, вручну його не вирівнюють. | `ruff format` |
| Іменування: функції, змінні, аргументи, модулі | `snake_case` | `N` |
| Іменування: класи й винятки | `PascalCase`, винятки із суфіксом `Error` | `N` |
| Іменування: константи | `UPPER_SNAKE_CASE` на рівні модуля | рев'ю |
| Мова ідентифікаторів | Лише англійська, без транслітерації. Назву предметного терміна беруть зі стовпця «Ідентифікатор у коді» файлу `spec/glossary.md` і записують у стилі Python: `checkInAt` → `check_in_at`, `pricePerNight` → `price_per_night`, `Booking` → `Booking`. Коди й статуси глосарія не змінюють: `DATES_UNAVAILABLE`, `BookingStatus.PENDING`. Терміни з розділу 2 глосарія не вживають. | рев'ю |
| Назви контракту API | Поля схем запитів і відповідей та параметри маршрутів збігаються з `api/openapi.yaml`, тобто записані в `camelCase`. Див. розділ «Винятки». | виняток із `N803`, `N815` |
| Імпорти | На початку файлу, три групи через порожній рядок: стандартна бібліотека, сторонні пакети, код проєкту. У кожній групі порядок алфавітний. Невикористаних імпортів немає. | `I`, `E402`, `F401` |
| Імпорти коду проєкту | Абсолютні, від пакета `src`: `from src.errors import ...` | рев'ю |
| Docstring-и: наявність | Обов'язкові для публічних модулів, пакетів, класів, функцій і методів у всьому коді, крім `tests/`. | `D1xx` |
| Docstring-и: мова | Текст українською, у термінах глосарія. | рев'ю |
| Docstring-и: форма | Стиль Google. Перший рядок — стислий зміст, стоїть одразу після `"""` і закінчується крапкою, знаком питання чи знаком оклику. Далі, за потреби, порожній рядок і деталі. | `D` (convention `google`) |
| Docstring-и: секції | Назви секцій лише англійською: `Args:`, `Returns:`, `Raises:`. Ruff розпізнає тільки їх. Під українською назвою секція не викличе помилки, але й не буде перевірена. Опис усередині секції — українською. | `D417`, рев'ю |
| Docstring-и: трасування | Якщо код реалізує вимогу, у docstring-у вказують її номер: `FR-13`, `AC-13.1`. | рев'ю |
| Docstring-и: FastAPI і Pydantic | Docstring обробника маршруту починається з `\f`, інакше він стане описом операції в OpenAPI. Docstring моделі Pydantic завжди потрапляє в схему, тому це один короткий публічний рядок без секцій. | рев'ю |
| Тести | Правила групи `D` у `tests/` вимкнено, решта правил діє. | `per-file-ignores` |
| Залежності FastAPI | `Depends` і `Query` оголошують через `Annotated`, а не як значення за замовчуванням: `user: Annotated[dict, Depends(require_user)]`. | `B008` |
| Сучасний синтаксис | Форми, доступні в Python 3.14: `X \| None`, `list[str]`. | `UP` |
| Типові помилки | Заборонено те, що ловлять pyflakes і bugbear: невикористані змінні, ланцюжок винятків без `from` тощо. | `F`, `B` |

Приклад docstring-а:

```python
def refund_share(initiator: str, hours_left: int) -> int:
    """Обчислює частку повернення p (FR-13).

    Args:
        initiator: Ініціатор скасування: GUEST, HOST або PLATFORM.
        hours_left: Кількість годин до моменту заїзду.

    Returns:
        Частку повернення у відсотках.

    Raises:
        RefundError: Якщо кількість годин від'ємна.
    """
```

## Винятки

Винятки задано в `per-file-ignores` у `pyproject.toml`.

| Файли | Правило | Підстава |
|-------|---------|----------|
| `tests/**` | `D` | Docstring-и в тестах не обов'язкові. |
| `src/schemas.py` | `N815` | Назви полів у `camelCase` задає `api/openapi.yaml`. |
| `src/routers/*.py` | `N803` | Назви параметрів у `camelCase` задає `api/openapi.yaml`. |
| `src/routers/*.py` | `D301` | Docstring обробника починається з `\f`, тому FastAPI не показує його в OpenAPI. Сирий рядок цей символ не створює. |
| `tests/test_listings_pagination.py` | `F811` | Фікстури pytest імпортовано, і їхні імена повторюються в аргументах тестів, тому спрацювання хибне. |

## Як запускати перевірку

Команди для PowerShell, запуск із кореня репозиторію.

Встановити залежності:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Перевірити, нічого не змінюючи:

```powershell
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
```

Показати зміни, які вніс би форматер:

```powershell
.venv\Scripts\python.exe -m ruff format --diff .
```

Виправити автоматично (ці команди змінюють файли):

```powershell
.venv\Scripts\python.exe -m ruff check --fix .
.venv\Scripts\python.exe -m ruff format .
```

Docstring-и в коді, написаному до прийняття цієї конвенції, ще не доповнено, тому перевірка поки що повідомляє про порушення групи `D`.
