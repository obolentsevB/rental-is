rental-is — внутрішній REST API (1.0.0)

Download OpenAPI specification:

Внутрішній програмний інтерфейс між клієнтом і сервером (SRS v1.1, §5.2). Модель ресурсів, правила URI, перелік операцій і модель помилок — docs/api-resources.md; терміни й ідентифікатори полів — spec/glossary.md.

Розширення операцій

  • x-req-ids — вимоги SRS із розділу 4 docs/api-resources.md.
  • x-acceptance-criteria — критерії прийняття цих вимог, які операція забезпечує.
  • x-side-effects — вимоги SRS, наслідки яких операція спричиняє, хоча вони не є її основною вимогою (запис журналу FR-22 — лише там, де він має окремий AC). Критерії прийняття цих вимог, які операція забезпечує, також входять до x-acceptance-criteria.
  • x-roles — хто може виконати операцію: anonymous — незареєстрований відвідувач; guest — обліковий запис, що діє як гість; host — обліковий запис, що діє як власник (власник конкретного житла — той, хто його опублікував); moderator — обліковий запис модератора; blocked — заблокований користувач (FR-01: вхід, свої повідомлення й поїздки, одне оскарження).

Помилки. Усі відповіді 4xx і 5xx — application/problem+json зі схемою Problem. Перелік кодів закритий (docs/api-resources.md, розділ 5). Для створення запиту на бронювання перевірки FR-07 виконуються в порядку ACCOUNT_BLOCKED, MIN_NIGHTS, OWN_LISTING, GUESTS_OUT_OF_RANGE, LISTING_UNPUBLISHED, CHECKIN_TOO_SOON, DATES_UNAVAILABLE; повертається перший код, що спрацював, і HTTP-статус визначає саме він.

Час і гроші. Ночі — дати YYYY-MM-DD; моменти — дата й час зі зсувом Europe/Kyiv; мітки часу журналу подій — UTC (NFR-07). Суми — UAH рядком з двома знаками після крапки (NFR-09).

Listings

Картка житла, пошук, зняття з публікації (FR-02, FR-04, FR-05)

Пошук житла

Вибірка житла в стані Published. Усі фільтри необов'язкові й поєднуються довільно. Місто — точний збіг без урахування регістру. Діапазон дат задається парою checkIn і checkOut і відбирає житло, що проходить повну перевірку доступності (FR-08) з технологічною перервою, чинною на момент пошуку. Інших фільтрів немає.

query Parameters
city
string
Example: city=Київ
checkIn
string <date>
Example: checkIn=2027-06-12

Дата заїзду; задається разом із checkOut.

checkOut
string <date>
Example: checkOut=2027-06-14

Дата виїзду; задається разом із checkIn і пізніша за неї.

guestsCount
integer >= 1
Example: guestsCount=2

Кількість осіб; лишається житло, де вона не перевищує maxGuests.

priceMin
string (Money) ^\d+\.\d{2}$
Examples: priceMin=1234.56

Нижня межа ціни за ніч, UAH.

priceMax
string (Money) ^\d+\.\d{2}$
Examples: priceMax=1234.56

Верхня межа ціни за ніч, UAH.

sort
string
Enum: "price_asc" "price_desc" "rating_desc"

price_asc, price_desc — за ціною за ніч; rating_desc — за неокругленою середньою оцінкою, житло без неприхованих відгуків у кінці.

Bookings

Запити й бронювання (FR-06–FR-09, FR-12, FR-13)

Створення запиту на бронювання

Створює бронювання в статусі PENDING, фіксує час заїзду, час виїзду, технологічну перерву, відсоток комісії, вартість проживання й комісію (FR-06, FR-15) і операцію оплати передоплати; власник отримує повідомлення. Інші запити в PENDING на ті самі ночі створенню не заважають.

Відмова не створює ні бронювання, ні платіжної операції й додає запис WARN із кодом до журналу подій. Перевірки FR-07 виконуються в порядку ACCOUNT_BLOCKED, MIN_NIGHTS, OWN_LISTING, GUESTS_OUT_OF_RANGE, LISTING_UNPUBLISHED, CHECKIN_TOO_SOON, DATES_UNAVAILABLE; повертається перший код, що спрацював. Тому схема не обмежує guestsCount і порядок дат: ці порушення мають власні коди, а не VALIDATION_FAILED.

Гість подає спір щодо бронювання, скасованого з ініціатором HOST, до моменту скасування + 14 діб. Подання журналюється рівнем INFO, усі модератори отримують повідомлення; спір з'являється в переліку звернень.

bearerAuth
path Parameters
bookingId
required
string <uuid> (Id)

Модератор встановлює підсумкову частку повернення, не більшу за чинну, з обов'язковою підставою. Рішення остаточне; стягнення з гостя і виплату власнику система фіксує за FR-15 і FR-16; гість і власник отримують повідомлення.

Appeals

Оскарження (FR-21)

Оскарження блокування або зняття

BLOCKING — заблокований користувач оскаржує блокування один раз до моменту рішення + 14 діб. UNPUBLISHING — власник оскаржує автоматичне зняття оголошень за FR-14 до моменту зняття + 14 діб. Подання журналюється рівнем INFO, усі модератори (зокрема той, хто заблокував) отримують повідомлення.

Authorizations:
bearerAuth
Request Body schema: application/json
required
subject
required
string
Enum: "BLOCKING" "UNPUBLISHING"

BLOCKING — блокування; UNPUBLISHING — автоматичне зняття оголошень за FR-14.

Рішення за оскарженням

GRANTED для блокування — розблоковує обліковий запис, повертає в публікацію оголошення, зняті через блокування, і видимість відгукам, прихованим через блокування; для зняття — повертає в публікацію оголошення, зняті за FR-14. Скасовані бронювання не відновлюються. Оскарження блокування не розглядає модератор, який заблокував. Заявник отримує повідомлення.

Events

Журнал подій (FR-22, NFR-06)

Журнал подій

Модератор бачить усі записи; гість — записи своїх бронювань; власник — записи своїх оголошень і бронювань свого житла. Журнал лише читається: операцій зміни чи видалення записів немає (NFR-06). Мітки часу — UTC.

Authorizations:
bearerAuth
query Parameters
bookingId
string <uuid> (Id)

Лише записи цього бронювання. Доступ за ролями не змінюється (AC-22.5): фільтр звужує лише записи, доступні поточному користувачу.

listingId
string <uuid> (Id)

Лише записи цього оголошення. Доступ за ролями не змінюється (AC-22.5): фільтр звужує лише записи, доступні поточному користувачу.
